# معماری پیشران — نسخه Local-first

## تصمیم‌های اجرایی فعلی

- Frontend: React + TypeScript + Vite
- تجربه وب: PWA و انتشار با GitHub Pages
- Android: Capacitor 7؛ یک کدبیس برای وب و APK
- Storage: IndexedDB به‌عنوان ذخیره‌ساز اصلی، localStorage به‌عنوان fallback
- Settings: تنظیمات محلی نسخه‌بندی‌شده، با آینه‌سازی کلیدهای مهم در localStorage
- Backup: خروجی و بازیابی JSON از صفحه تنظیمات
- Authentication: ورود، ثبت‌نام، نشست کاربر و مجوزدهی فعلاً پیاده‌سازی/فعال نمی‌شوند
- Backend: FastAPI و PostgreSQL در مخزن باقی می‌مانند اما رابط فعلی به آن‌ها وابسته نیست

## لایه‌ها

1. **Presentation:** صفحات، layout، فرم‌ها و اجزای UI
2. **Features:** داشبورد، پروژه‌ها، مدل مالی، مهندسی، بازار، ریسک و گزارش
3. **Core / Domain:** مدل‌های پروژه، مفروضات، سناریوها و قواعد محاسباتی
4. **Core / Services:** repositoryها، تنظیمات، اعتبارسنجی و پشتیبان‌گیری
5. **Infrastructure:** IndexedDB، localStorage، فایل‌ها و bridge اندروید
6. **Delivery:** Vite/PWA، GitHub Pages و Capacitor

قانون وابستگی: صفحات فقط از سرویس‌ها و repositoryهای لایه Core استفاده کنند؛ دسترسی مستقیم به IndexedDB/localStorage از داخل صفحات مجاز نیست.

## سیاست ذخیره‌سازی محلی

- IndexedDB مخزن اصلی داده‌های ساختاریافته است.
- در صورت عدم دسترسی یا خطای IndexedDB، عملیات به localStorage fallback می‌شود.
- تنظیمات کوچک و ضروری برای boot سریع در localStorage mirror می‌شوند.
- کلیدها باید namespace و schema version داشته باشند.
- مهاجرت نسخه‌ای باید قابل بازبینی باشد و قبل از حذف داده قدیمی صحت داده مقصد بررسی شود.
- عملیات export/import باید نسخه schema و زمان تهیه پشتیبان را نگه دارد.
- داده‌ها تا زمان فعال‌سازی صریح قابلیت Sync، فقط محلی هستند.

## سیاست Authentication

در نسخه Local-first هیچ صفحه Login/Register، token، refresh token یا الزام حساب کاربری وجود ندارد. قراردادهای احتمالی احراز هویت فقط در مستندات آینده باقی می‌مانند و نباید مانع اجرای برنامه شوند.

## تنظیمات هم‌راستا با Namello

- حالت روشن/تیره/مطابق سیستم
- پوسته رنگی
- زبان و جهت نوشتار
- تراکم چیدمان
- رفتارهای ایمنی مانند تأیید حذف
- وضعیت و ظرفیت ذخیره‌سازی
- تهیه و بازیابی پشتیبان

## فازهای بعدی

1. تکمیل repositoryهای محلی برای تمام موجودیت‌ها
2. مدل مهندسی و بازار با ذخیره خودکار
3. مدل مالی و سناریوها
4. خروجی گزارش و پشتیبان کامل
5. تست آفلاین، مهاجرت داده و بازیابی
6. در صورت نیاز محصول: فعال‌سازی اختیاری Sync و Authentication در یک فاز جداگانه
